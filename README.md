# 📦 Система управления заказами

Тестовое задание для позиции Middle/Senior React-разработчика. Приложение для управления списком заказов с поддержкой CRUD-операций, inline-редактирования, пагинации и персистенции в localStorage.

## 🏗 Архитектура

```
src/
├── api/              # API-слой (моки → реальные запросы)
├── components/       # React-компоненты
│   ├── common/       # Переиспользуемые UI-компоненты
│   ├── orders/       # Компоненты списка заказов
│   └── order-details/# Компоненты деталей заказа
├── constants/        # Константы приложения (маршруты и т.д.)
├── context/          # React Context (клиентское состояние)
├── hooks/            # Кастомные хуки
├── mocks/            # Моковые данные для разработки
├── pages/            # Страницы (route-level компоненты)
├── providers/        # Провайдеры (React Query, тема и т.д.)
├── services/         # Сервисы (localStorage и т.д.)
├── test/             # Настройка тестового окружения
├── types/            # TypeScript типы доменной области
└── utils/            # Чистые утилитные функции
```

### Ключевые решения

| Решение | Обоснование |
|---------|-------------|
| **Vite** вместо CRA | CRA deprecated, Vite — быстрее и современнее |
| **React Query** | Серверное состояние (загрузка, кэширование, refetch) |
| **React Context** | Клиентское состояние (редактирование, unsaved changes) |
| **MUI** | Компонентная библиотека с полной типизацией |
| **TypeScript strict** | Максимальная типобезопасность на этапе компиляции |
| **Vitest** | Быстрый тест-раннер, совместимый с Vite |
| **Path aliases (@/)** | Чистые импорты без относительных путей |

### Разделение ответственности

- **Серверное состояние** → React Query (`useOrdersQuery`)
- **Клиентское состояние** → React Context (`OrdersContext`)
- **Персистенция** → Service layer (`storageService`)
- **Валидация** → Pure functions (`validation.ts`)
- **UI** → Компоненты с `useOrderForm` хуком
